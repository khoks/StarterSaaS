# auto-pr

The third and final skill in the Stop hook chain. After `harvest-knowledge` has updated the prose docs and `work-tracking` has updated `project/`, this skill turns those changes into a real PR on `main`.

## When to skip

If both prior skills said "nothing to persist" AND `git status --porcelain` is empty, say so explicitly:

> auto-pr: nothing to push.

Then mark the session housekept (per the Stop hook) and stop. Do **not** create empty commits or branches.

## Pre-flight checks

Run these in order. The first that fails determines the fallback path.

1. **Dirty?** `git status --porcelain` — if empty, skip cleanly (see above).
2. **In a git repo?** `git rev-parse --is-inside-work-tree` — if not, hard error and abort.
3. **`gh` available?** `command -v gh` — if missing, fall back to commit-on-main-locally (no push, no PR). Tell the user.
4. **`gh` authenticated?** `gh auth status` (silent on failure) — if not, fall back to commit-on-main-locally and tell the user to `gh auth login`.
5. **Remote `origin` exists?** `git remote get-url origin` — if not, commit-on-main-locally only. Tell the user.

If all pre-flight checks pass, proceed to the PR cycle.

## PR cycle (happy path)

1. **Branch name.**
   - If a `session_id` is in scope (Stop hook input passed it through, or you can read it from `.claude/state/`), use `auto/<session-id-short>-<utc-yyyy-mm-dd>` (truncate session_id to 8 chars).
   - Else use `auto/manual-<utc-yyyy-mm-dd-hhmm>`.
   - If the branch already exists locally (rare — same session ran the skill twice), append `-2`, `-3`, etc.
2. **Create branch.** `git checkout -b <branch>`.
3. **Stage.** Stage all changes under `docs/`, `project/`, `.claude/` only:
   ```bash
   git add docs/ project/ .claude/
   ```
   Do **not** auto-stage source code (`apps/`, `packages/`, `services/`, `infra/`, `scripts/`). If those have unstaged changes, surface them in your handoff and let the user commit them via a Story-driven PR.
4. **Compose commit message.** Derive subject from changed file groups. Examples:

   | Changed under | Subject |
   |---|---|
   | only `docs/vision/` | `docs(vision): harvest from session <id>` |
   | only `docs/decisions/` | `docs(decisions): log decisions from session <id>` |
   | only `docs/architecture/` | `docs(architecture): adr update from session <id>` |
   | only `project/` | `chore(project): tracking updates from session <id>` |
   | only `.claude/` | `chore(claude): skill / hook updates from session <id>` |
   | mixed (≥2 of above) | `chore(housekeeping): harvest + tracking from session <id>` with body listing the categories |

   Always include a body line listing the changed file paths (one per line) for diff-able audit.

   Append:
   ```
   Co-Authored-By: Claude Opus 4.7 <noreply@anthropic.com>
   ```

5. **Commit.** `git commit -m "$(cat <<'EOF' ... EOF)"` — use heredoc for multi-line.
6. **Push.** `git push -u origin <branch>`. On rejection (e.g., non-fast-forward), abort, surface the git error verbatim, leave the local branch intact for the user to investigate.
7. **Open PR.** `gh pr create --title "<subject>" --body "$(cat <<'EOF' ... EOF)" --base main --head <branch>`. Body template:
   ```
   ## Story / Epic

   Auto-PR — housekeeping output from a Claude Code session. No Story association.

   ## Summary

   - <one-line per changed category>

   ## Test notes

   Doc / tracking changes only. Verify by reading the diff.

   ## Checklist

   - [x] Story `status` updates (if any) reflected in `BOARD.md`
   - [x] No source-code changes; no secrets; no large binaries
   - [ ] If architectural: ADR added/updated in `docs/architecture/` (auto-applied if applicable)
   - [ ] If novel-idea-flagged: entry added to `docs/vision/NOVEL_IDEAS.md` (auto-applied if applicable)
   - [ ] If decision-grade: entry added to `docs/decisions/DECISIONS_LOG.md` (auto-applied if applicable)

   _Generated by the `auto-pr` skill. Branch: `<branch>`. Session: `<session-id>`._
   ```
8. **Enable auto-merge.** `gh pr merge --auto --squash <pr-number>`. If the repo isn't configured for auto-merge or branch protection forbids it, the command exits non-zero — surface the error verbatim, leave the PR open for manual merge.
9. **Report.** 2–3 lines:
   ```
   auto-pr: opened PR #<n> on branch <branch>. Auto-merge: <enabled|blocked: reason>. URL: <url>.
   ```

## Fallback path: commit-on-main-locally

When `gh` is missing/unauth'd or no remote exists, do **not** create a branch. Instead:

1. Stage as above (`docs/`, `project/`, `.claude/` only).
2. Compose the same commit message.
3. `git commit` directly on `main`.
4. Report: `auto-pr: no remote / gh; committed locally on main as <sha>. Set up the remote with: gh repo create khoks/StarterSaaS --private --source=. --remote=origin --push`.

This is the bootstrap-day pattern — the very first commit lands this way before the GitHub remote exists.

## Failure modes (explicitly handled)

| Symptom | Cause | Action |
|---|---|---|
| `git push` rejected | Branch protection / non-fast-forward / network | Abort, surface git error, leave branch intact |
| `gh pr create` fails | Auth expired, repo not on GitHub, network | Abort, surface error, branch + commit remain |
| `gh pr merge --auto` fails: "auto-merge not allowed" | Branch protection not set up to allow auto-merge | PR stays open, instruct user to enable auto-merge in repo settings |
| `gh pr merge --auto` fails: required CI not passing | CI hasn't completed or failed | PR stays open, no further action |
| Merge conflict in auto-merge queue | Concurrent PR landed first | PR stays open, GitHub UI surfaces conflict, user resolves |
| `git status` shows source-code changes outside `docs/` `project/` `.claude/` | A code-touching session forgot to commit via Story workflow | Skip those paths, commit only doc/tracking changes, surface a warning to the user |

## What NOT to do

- Do **not** force-push (`git push -f`). Linear history is enforced; force-push is forbidden without explicit user approval.
- Do **not** auto-stage source code paths (`apps/`, `packages/`, `services/`, `infra/`, `scripts/`). Those land via Story-driven PRs that the assistant authors deliberately, not via housekeeping.
- Do **not** commit secrets or `.env*` files (the `.gitignore` already excludes these — but double-check the `git status` output).
- Do **not** commit `node_modules/` or large binaries (excluded by `.gitignore`, but the same defensive check applies).
- Do **not** rebase or rewrite history.
- Do **not** delete branches automatically. Once `gh pr merge --auto` lands, GitHub deletes the head branch on merge per repo settings — don't pre-empt that.
- Do **not** open multiple PRs from the same session. One session → at most one auto-PR.

## Boundary with harvest-knowledge and work-tracking

`harvest-knowledge` writes **prose docs**. `work-tracking` writes **structured items**. `auto-pr` writes **git history + PR**.

Run order in the Stop hook: `harvest-knowledge` → `work-tracking` → `auto-pr`. By the time `auto-pr` runs, the working tree should contain *all* the doc + tracking changes those skills produced (plus any other stale changes from the session). `auto-pr` is the *only* skill that touches git.
